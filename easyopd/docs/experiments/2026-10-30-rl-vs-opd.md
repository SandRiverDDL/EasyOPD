# 2026-10-30 同预算下 RL（GRPO / DAPO）和 vanilla OPD 对比

- 代码：`easyopd/methods/vanilla_opd/`、`experiments/07_opd_repro/configs/exps/1030_rl/{opd,grpo,dapo}.yaml`、`experiments/07_opd_repro/configs/protocols/{opd,rl}_b32n8r8k.yaml`
- 状态：done（10-31 补写）
- 结论（一句话）：部分成立。MATH-500 上 vanilla OPD 在 step 20 领先 GRPO 4.7 分、领先 DAPO 15 分；step 60–200 领先 DAPO 3.7–5.6 分，和 GRPO 的差只有 2.2–2.7 分，在判据内分不开。AIME 上三者分不开。

## 要回答的问题与判据

每步 rollout 数和长度相同时，只靠 verifier 奖励的 RL（GRPO / DAPO）和只靠 teacher logp 的 vanilla OPD 谁学得快、谁最终更高。

- 判据：MATH-500 avg@4（500 题）单个 ckpt 的 σ 约 1 分，差 > 3 分才算差异；AIME avg@8（30 题）差 < 5 分不下结论。
- ckpt 用固定网格 step 20/60/100/200，不按 dev200 挑点，避免选择偏差。
- 适用范围：单 seed，Base 1.7B 学生，≤ 200 步，8192 长度。

## 配置

- student `Qwen3-1.7B-Base-imend`；OPD 的 teacher 是 `Qwen3-4B`；数据 train_en（DAPO 去重）。
- 三个 run 都是每步 32 题 × 8，response 8192，lr 1e-6，fp32 主权重，seed 1。OPD 用 `terminal_stop=cross_eos`。验证 math500_dev200 每 20 步，只权重 ckpt 每 20 步。
- OPD 原定 100 步，用 `launch_resume200.sh` 续到 200 步。RL 两个 run 直接跑 200 步。
- 唯一的差异是学习信号：GRPO / DAPO 用 verifier 奖励，OPD 用 teacher 的逐 token logp。
- 代码版本：commit ff0a8ca 加工作区改动，见各 run 的 `code_version.txt`。
- 10-30 先起的 `rl200s20_{grpo,dapo}` 用的是 lr 2e-6，手动停在 28 / 32 步，不计入。

## 结果

离线评测的设置是 T=0.6、top_p 0.95、8192 tokens、enable_thinking=false。MATH-500 是 avg@4，括号里是截断比例。student_init 为 37.9（27%），teacher Qwen3-4B 为 83.5（1%）。

| step | vanilla OPD | GRPO | DAPO |
|---|---|---|---|
| 20 | 61.2 (5%) | 56.5 (7%) | 46.0 (14%) |
| 60 | 65.2 (12%) | 62.9 (10%) | 59.6 (3%) |
| 100 | 67.9 (8%) | 65.2 (10%) | 61.5 (3%) |
| 200 | 69.4 (6%) | 67.2 (8%) | 65.3 (1%) |

AIME24 / AIME25 avg@8（30 题），step 200 的结果：OPD 8.3 / 7.9，GRPO 9.2 / 5.8，DAPO 7.9 / 5.0；student_init 0.8 / 3.8。全部差 < 5 分，分不开。AIME 截断比例：OPD 19–57%，GRPO 16–49%，DAPO 6–27%，所以 8K 下 AIME 主要在测长度。

训练时 dev200（n=1，σ 约 3.4 分）的 step 0 → 100 → 200：OPD 0.38 → 0.67 → 0.705，GRPO 0.31 → 0.655 → 0.66，DAPO 0.31 → 0.64 → 0.655。step 0 的差来自 reward 函数不同（OPD 和 RL 的验证分数口径不同，未逐项核对），只看增量。

## 观察与后续

- OPD 前 20 步最快，之后三者的斜率接近。DAPO 起步最慢，step 20 截断率 14%，之后降到 1–3%。
- RL 第 1 步 32 组里 26 组全错（`rl/group_all_wrong`），Base 学生在 DAPO 题上几乎拿不到奖励信号，这可能是 RL 起步慢的原因（推断，未做消融）。
- OPD 的输出更长（MATH 截断 6–12%，DAPO 1–3%）。32K 重评能区分"会做但写不完"和"不会做"，目前没做。
- 只有单 seed；要把 OPD vs GRPO 的 2–3 分差确认下来，需要第二个 seed 或更大的评测集。
