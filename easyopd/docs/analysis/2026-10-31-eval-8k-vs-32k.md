# 2026-10-31 8K 评测截断对 Semi-OPD / OPD 对比的影响

- 代码：`experiments/07_opd_repro/scripts/evaluate.py`（trunc = vLLM `finish_reason == "length"`）
- 状态：open（只重评了各自 8K 下最好的一个 ckpt）
- 结论（一句话）：8K 和 32K 的排序一致（OPD > Semi-OPD），但 8K 把差距压小了约 3 倍（3.7 → 11.6 分）；8K 分数的下降可以完全用"写不完判错"解释，不能拿来比较方法。

## 问题

semi100_semi / semi100_opd 用 8K 上限评测时，截断率很高（semi step100 的 aime24 为 78%），被截断的样本正确率只有 0–5%，而写完的样本在 aime24 上正确率达 96%。所以要判断：8K 分数能不能代表模型的能力排序。

## 证据

两个 run 各取 8K 四集平均最好的 ckpt：`semi_opd/1030_0828_semi100_semi` 的 step 20（44.9），`vanilla_opd/1030_0854_semi100_opd` 的 step 60（48.1）。用 32K 重评 aime24 / aime25 / amc23，其余设置与 8K 相同：T=0.6，top_p=0.95，每题 8 个样本，seed 0，8 卡。结果写在各 run 的 `eval/results.jsonl` 里，tag 为 `*_32k`。下表的"32K 截到 8K"，是把 32K 的样本中长度超过 8192 的一律判错，用来检查两次运行是不是同一个分布。

| 模型 | 数据集 | 8K | 32K | 32K 截到 8K | 32K 截断率 | 每题 r(8K,32K) |
|---|---|---|---|---|---|---|
| semi step20 | aime24 | 22.1 | 24.2 | 22.5 | 21.7% | 0.88 |
| | aime25 | 16.7 | 22.1 | 19.2 | 10.4% | 0.87 |
| | amc23 | 59.7 | 63.7 | 59.4 | 1.9% | 0.81 |
| opd step60 | aime24 | 27.1 | 43.8 | 30.0 | 23.8% | 0.83 |
| | aime25 | 21.2 | 28.3 | 22.9 | 18.8% | 0.89 |
| | amc23 | 61.3 | 72.8 | 59.7 | 3.4% | 0.88 |

三集平均：semi 8K 为 32.8，32K 为 36.7；opd 8K 为 36.5，32K 为 48.3。

## 结论与根因

已验证的部分：
- 两次运行是一致的。"32K 截到 8K"和真实 8K 的分数差在 3 分以内。每题正确率的相关系数是 0.81–0.89，说明哪些题会做、哪些不会，8K 和 32K 判断得差不多。
- 8K 低估的幅度取决于模型写多长。OPD 的平均长度更长（aime24 上约 16.7K tok，semi 约 13.4K），被 8K 截掉的正确答案也更多：opd 在 aime24 上从 27.1 涨到 43.8，semi 只从 22.1 涨到 24.2。
- 32K 下仍有约 20% 的 aime 样本被截断，所以 32K 的分数也是下界。

未验证 / 偏差：
- ckpt 是按 8K 分数挑的。8K 偏爱写得短的 ckpt，semi step20 正好是它截断率最低的一步。semi 后期的 ckpt 在 8K 下截断率高，但写完的样本正确率很高，到 32K 下可能分数更高。所以"semi 输给 opd 11.6 分"还不是同口径的结论，需要用 32K 评 step 60/80/100，按论文 Table 1 的口径对比。
- semi 在 aime24 上 8K 内写完的比例，两次运行不一致：8K 那次是 50.8%，32K 那次是 42.9%（每组 240 个样本，差距约 2.5σ）。原因没有查，可能和 8K 那次用的是旧版 evaluate.py（按数据集分别调用 generate）有关。

## 影响的决定

- 07 轮的 OPD 方法对比不再用 8K 分数下结论，至少要用 32K。
